## §6 — Case System

**A Case** is a specific, binding application of SVE principles to a concrete scenario, forming precedent.

**Format:** `SVE-Case-[NN]-[Title]-v[X.Y].md`

**Required components:** Scenario · Violation · Evidence standard · Penalty formula · Precedent value · Framework references.

**Lifecycle:**
```
DRAFT → REVIEW → VOTE (67% Veche) → ACTIVE → ARCHIVED
```

**Activation process:**
1. Proposal submitted with all required components.
2. Community discussion (2–4 weeks).
3. Elder Brothers review (legal validity, SVE alignment).
4. 4+1 AI Oracle validation (Core Principles compliance).
5. Veche vote (67% threshold). If deadlocked → Coin decides.
6. Custodian signature + hash publication → binding.

**Fast-track:** Author & Initial Custodian may expedite urgent cases (48-hour vote).

**Who can propose:** Anyone — community members, attorneys, victims, researchers, organizations.

**Versioning:** Minor updates (v1.x) for clarifications; major updates (v2.x) for changed penalties or evidence standards. Same activation process applies. Cases filed under superseded versions remain valid — no retroactive changes.

**Legal standing:** Cases are SVE internal law. In government courts, cited as evidence; in SVE arbitration, binding.

**Cases reference** appendices A–G and each other. Appendices reference cases back. This bidirectional linkage forms a coherent, self-consistent system.
